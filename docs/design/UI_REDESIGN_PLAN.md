日期：2026-10-18。状态：规划草案；用户已选择“浅色底、蓝绿点缀、清晰专业”。本轮实际修改限于周课表遮挡修复，尚未替换正式名称或全面换肤。

查看：[可点击界面草案](ui-concept.html) · [桌面草案截图](evidence/ui-concept-desktop.jpg) · [手机草案截图](evidence/ui-concept-mobile.jpg) · [周课表修复与验收](WEEKLY_GRID_FIX.md)。

## 名称与产品表达

| 候选 | 表达 | 取舍 |
|---|---|---|
| **课序（建议）** | 课程有序、一天有序 | 简短，保留课表识别度，适合承载待办、专注和 AI |
| 课刻 | 课程与时间 | 更轻巧，偏课程与时间安排 |
| 拾时 | 整理零散的学习时间 | 温和、覆盖专注，但课表识别度弱一些 |

推荐显示名“课序”，副标题“课表 · 待办 · 专注”。名称目前为候选，不作为已定品牌。首轮只调整用户可见名称、图标、页面标题与安装文案。

继续保留已有站点 origin、IndexedDB 名称与版本、备份格式和密钥、PWA manifest `id`。改显示名称不应让用户出现另一份空数据库或重复安装；仓库和包标识不随视觉改造重命名。

## 信息架构

保留课表为默认入口。手机底栏统一为“课表 / 今日 / 待办 / 助手 / 我的”；桌面使用同样顺序的侧栏，帮助放在下方。各入口复用现有路由，不重写业务链路。

| 入口 / 路由 | 内容层级 | 关键调整 |
|---|---|---|
| 课表 `/timetable` | 学期与教学周 → 日/周/全部 → 课程和考试 | 顶部一条主工具栏；添加课程为主按钮，导入/考试/学期管理放次级菜单；周次紧邻日期 |
| 今日 `/focus` | 下一项安排 → 今日时间线 → 待办 → 专注计时 | 复用原专注页；计时是执行工具，避免再加统计仪表盘；完成仍由用户确认 |
| 待办 `/todos` | 未完成 / 已完成 → 截止时间与来源 → 循环规则 | 列表和轻分组，减少重复卡片；考试待办进入对应考试管理 |
| 助手 `/ai` | 当前课表上下文 → 对话 → 待确认动作 | 新增/更新/删除有明确目标及前后变化；确认前不写库；不让悬浮控件挡住输入 |
| 我的 `/settings` | 本机数据与快照 → 作息与学期 → 外观 → AI 连接 → 帮助 | 用分组入口或页签替代长表单堆叠；“本机已保存”和“最近云备份”分别展示 |

全局顶栏只保留品牌、当前页/学期和必要操作。去掉工作区侧边统计、表情字符、重复品牌与“本机已连接”等不精确状态；不新增账号或同步中心。

## 视觉基线

保留 React + Ant Design，先统一 CSS 变量与 Ant Design token，避免三层样式分别覆盖同一控件。预览见 [ui-concept.html](ui-concept.html)，全部为合成示例。

| Token | 浅色方案 | 用途 |
|---|---|---|
| `canvas` | `#F5F8FA` | 页面背景 |
| `surface` | `#FFFFFF` | 内容表面 |
| `text` | `#173244` | 主文字 |
| `text-secondary` | `#536B78` | 时间、地点、辅助说明 |
| `border` | `#DDE6EB` | 细分隔线 |
| `brand` | `#167D9A` | 主要操作、当前导航 |
| `brand-soft` | `#E7F4F7` | 选中与课程浅底 |
| `teal` | `#0C7C72` | 完成、正常本机保存状态 |
| `warning` | `#8A4B00` / `#FFF4E5` | 时间冲突、待确认 |
| `danger` | `#B42318` / `#FEF3F2` | 考试强调、错误与删除 |

- 字体使用系统中文无衬线：`system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`。不依赖外部字体请求；只有时间和对齐数字使用等宽数字。
- 桌面正文14–15px，手机正文15–16px，输入框至少16px。保留用户字号偏好，放大后布局增长。
- 间距为4/8/12/16/24/32px；普通控件圆角8px，必要面板10–12px。使用留白和1px分隔组织信息，减少厚边框、嵌套卡片和高饱和色块。
- 手机有效点击区域至少44px。主要动作每个工作区通常一个；次要动作保持可点击文字或菜单入口。
- 课程使用稳定、有限的浅色填充；考试、冲突和完成配合文字/图形，不只靠颜色。
- 暗色主题保留，但与浅色共用蓝绿品牌语义；逐项校验对比度，不继续使用“浅色粉、深色紫”两套身份。

## 周课表显示规则

本轮先修复结构，后续按上述视觉方案换肤：

1. 课程与考试都用显式行列坐标，跨节范围不依赖 CSS Grid 自动补位；日期不得错列。
2. 时间重叠的安排按轨道并列，链式重叠不被合并成“只显示第一门”；每项都可点击和键盘进入。
3. 节次行有可读下限，内容增加时允许增长；长课名、英文、地点、教师换行，字号放大后仍完整可读，不压缩12节强塞进一屏。
4. 手机默认日程；周视图保留可读列宽，允许在课表区域横向与纵向滚动。表头/节次栏吸附时必须设置清晰的交界层级，不覆盖课程。
5. 考试保留真实时间。超出作息的考试即使近邻展示也要明确标注；没有作息时仍提供可点击的安排列表。
6. 底部导航、安装/更新、快速导入不覆盖最后一节或编辑入口。不能以 hover 作为手机的唯一详情入口。

## 实施顺序与文件范围

| 批次 | 具体范围 | 涉及文件 | 验收后再进入下一批 |
|---|---|---|---|
| A 本轮 | 周课表定位、并列、文字与缩放修复 | `TimetableGrid.tsx`、`utils/timetableLayout.ts`、独立课表CSS及回归 | 课程/考试全可达，长文本不裁切，跨节不错列 |
| B 设计基线 | 定显示名与图标；统一色板/字体/间距；导航骨架 | `theme.tsx`、`index.css`、`mobile.css`、`AppLayout.tsx` | 今日/周表/AI三个关键界面先审核；不动数据结构 |
| C 高频页面 | 课表主工具栏、详情、待办、今日执行布局 | `TimetablePage`、`CourseDayView`、课程/考试弹窗、`TodosPage`、`FocusPage` | 日/周/列表一致，编辑失败保留草稿，原表单scope保护保持 |
| D 设置与助手 | 设置分组、快照状态、AI提案信息层级 | `SettingsPage`、备份设置、AI聊天/输入/提案组件 | 恢复仍预览确认；AI逐卡确认；输入法及附件不被遮挡 |
| E 品牌与回归 | 页面标题、PWA显示名/图标、安装文案、帮助与发行 | `index.html`、PWA构建插件、`PwaStatus`、帮助与包文档 | 保留manifest id/origin/数据库；更新后本机记录不变 |

交付紧张时，第一批完整视觉改造优先覆盖品牌显示、导航、课表与待办；今日、助手和设置随后独立提交。每批附截图与受影响回归，避免把功能修复与整套皮肤混成一次不可对照的大改。

## 验收清单

- 320/360/390/430px手机；768/1024/1440px宽度。页面本身不横向溢出，周表的横向滚动有明确边界。
- 单节长中文/英文课程、连续四节、同起点三项、链式冲突、课程与考试重叠、跨上午下午、最后一节、稀疏节次。
- 100%/150%/200%课表字号，以及亮/暗主题；名称、地点、教师不被邻块或吸附表头遮住。
- 鼠标、触摸、Tab/Enter均可进入每项详情；编辑后返回原视图位置。
- 离线重开、快照恢复、旧编辑器失效、AI确认、版本更新恢复点继续通过。
- 品牌或导航更改后不新建空的数据空间、不修改密钥、不把云端改回业务主库。
