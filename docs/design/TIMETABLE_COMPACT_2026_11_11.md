# 窄屏课表：一屏看完整周（2026-11-11）

## 问题

课表网格在 `TimetableGrid` 里用内联样式写死了最小宽度：

```ts
minWidth: 56 + 7 * 112  // = 840px
gridTemplateColumns: `56px repeat(7, minmax(112px, 1fr))`
```

手机宽度约 390px，网格却有 840px，只能横向滚动；用户必须缩放才能看到完整一周。行高下限 68px × 12 节，竖屏也放不下全部节次。

同时页面上有几处次要信息占用了竖向空间：

- 标题下的学期起止日期与总周数
- 周次文字里的“/ 共 18 周”
- “点击课程或考试可查看或编辑；可横向滚动查看完整一周”提示
- 节次列的起止时间

## 改动

### 1. 网格尺寸改为响应式变量

`TimetableGrid.tsx` 不再写死像素，改用 CSS 变量参与计算：

```ts
minWidth: calc(var(--tt-axis-width) + lanes * var(--tt-day-min))
gridTemplateColumns: var(--tt-axis-width) + minmax(n * var(--tt-day-min), 1fr)
gridTemplateRows: auto + minmax(calc(var(--tt-row-min) * var(--tt-scale)), 1fr)
```

断点值（`timetable-grid.css`）：

| 宽度 | 节次列 | 每天最小宽 | 行高下限 |
|---|---|---|---|
| > 900px | 56px | 112px | 68px |
| ≤ 900px | 44px | 64px | 56px |
| ≤ 640px | 26px | 0px | 0px（按可用高度等分） |

### 2. 清掉旧规则里的固定高度

`day-agenda.css` 里还留着早期布局的 `.tt-cell { min-height: 42px }` 和 `.timetable-grid { min-width: 820px }`。前者特异性更高，会把每一节重新撑到 42px——这就是“7 天已经放得下，但上下仍要翻页”的原因。已删除这两条遗留规则。

### 3. 窄屏去掉次要信息

- 隐藏学期日期、总周数、网格上方提示、星期下的日期
- 节次列只保留节号，不再显示起止时间
- 课程块隐藏地点/教师/节次副文本，只保留课程名与颜色
- 课程名最多两行（矮屏一行），超出裁切
- 表头、工具条、页面间距压缩；`.tt-scroll` 改为 flex 容器，网格占满剩余高度

## 实测（iframe 模拟视口 + `--app-height`，10 门课 / 12 节 / 7 天）

| 视口 | 横向溢出 | 纵向滚动 | 每节行高 | 每天列宽 |
|---|---|---|---|---|
| 390×844 | 无 | 无 | 44px | 47px |
| 412×915 | 无 | 无 | 50px | 51px |
| 360×720 | 无 | 无 | 34px | 42px |
| 360×640 | 无 | 无 | 27px | 42px |
| 320×568 | 无 | 无 | 22px | 36px |

390×844 下：`scrollWidth = clientWidth`、`scrollHeight = clientHeight`，8 个表头（节次 + 7 天）、12 个节次行、10 门课全部在首屏，课程名无裁切。320×568 时课程名按一行截断，换取整周不滚动。

## 边界

- 只在浏览器与模拟视口验证，未在真机复验。
- 320px 级窄屏会把课程名截为一行；点开课程仍可看到完整信息。
- 桌面（>900px）维持原来的可读宽度与横向滚动策略。
