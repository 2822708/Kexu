# 手机端滑动翻页修正（2026-11-12）

来自真机反馈的三个问题：页面下半空白处不能滑、翻页后旧页闪一下、两页连接处没有间距。均已复现、修复并复验。

## 1. 页面下半空白处不能滑动

**现象**：课表/任务等内容较短的页面，只有上半部分能滑动翻页，下半屏空白区域无反应。

**定位**：`.app-content` 高 716px，而 `.swipe-viewport` 只有 493px（`flex: 0 0 auto`，高度只等于内容高度）。手势监听挂在 viewport 上，空白区域属于 `.app-content` 的剩余空间，事件根本到不了监听器。实测在 `y = 756` 处滑动，`transform` 保持为空。

**改动**：

- `.swipe-viewport` 改为 `flex: 1 0 auto`，撑满内容区剩余高度；内容超出一屏时仍随内容增高，由 `.app-content` 纵向滚动。
- 手势监听从 viewport 改挂到最近的 `.app-content`（含 12px 内边距），监听解除时同步移除。

**复验**：同一位置滑动后 `location.pathname` 由 `/tasks` 变为 `/ai`，viewport 高度 692px（76–768），与内容区一致。

## 2. 翻页后旧页闪一下

**现象**：松手完成翻页的瞬间，上一页内容会在新页位置短暂出现。

**定位**：逐帧采样（`requestAnimationFrame`）显示，动画结束后代码先执行 `track.style.transform = 0` 再 `setNeighbor(null)`，而 `navigate()` 触发的路由更新是异步的：这一帧 `pathname` 已经是 `/ai`，但 `.swipe-page` 渲染的仍是旧的任务页，且轨道已经归零 —— 于是旧页在 0 位停了一帧（实测约 43ms）。

**改动**：提交时不再立刻归零，改为记录待落地路由（`pendingResetRef`），在 `useLayoutEffect` 中等到 `location.pathname` 与目标一致、新页已挂载后再归零并移除邻页；同时保留 600ms 兜底（例如路由被拦截时不会把轨道卡在偏移位置）。

**复验**：逐帧采样中不再出现“轨道为 0 且仍是旧页”的帧；切到 `/settings` 的那一帧直接是设置页内容。

## 3. 两页连接处没有间距

**现象**：拖动时相邻两页首尾相接，像一整块内容被切开。

**定位**：邻页定位为 `left/right: 100%`，与当前页边界完全重合（实测当前页右边界 238px，邻页左边界也是 238px，缝隙 0）。

**改动**：

- 新增 `--swipe-gap`（由组件内 `GAP_PX = 12` 写入轨道内联样式，CSS 与动画共用同一数值）。
- 邻页改为按 `data-side` 定位：`calc(100% + var(--swipe-gap))`。
- 提交动画的目标位移改为 `页面宽度 + 缝隙`，邻页正好落到可视区 0 位，归零时不跳动。

**复验**：拖动时当前页右边界 238px、邻页左边界 250px，缝隙 12px；反向拖动为 132px / 144px，同样 12px。

## 验证

- `npm run typecheck`、`npm run lint`、`npm run build` 通过；前端回归 240/240 通过。
- 无头 Chromium（390×844，触摸模拟）：空白区滑动生效、反向滑动生效、短距离拖动回弹且不残留位移、纵向滑动仍能滚动页面（settings 页 `scrollTop` 0 → 669）且不会误翻页。
- 逐帧采样确认提交过程没有旧页帧。

## 边界

- 仍未在 Android APK / Windows 外壳真机复验，只有浏览器触摸模拟。
- 间隙固定 12px；如果后续做成可按设置调整，需要同时改 `GAP_PX` 与 `--swipe-gap` 的单一来源。
- 首末页的阻尼逻辑未改动。
