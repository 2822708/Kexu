# 设备自动登录

更新日期：2026-09-28

打开应用时不再要求输入账号 API Key。首次打开时，浏览器通过 Web Crypto 生成 32 字节随机凭据并保存在本站本地存储中，后端自动创建普通设备工作区。之后打开同一站点时复用该凭据和原有数据。

## 身份与数据

- 设备身份实际绑定浏览器配置和站点地址，不采集硬件指纹、MAC 地址或 IP 作为身份。其他浏览器、隐私窗口、不同站点地址或清除网站存储后会成为新设备；不会自动跨设备同步。
- 已保存的有效旧账号和 Windows 桌面端注入的凭据优先复用，原有课程、待办和权限保持不变。网络失败保留原凭据并提供重试，不静默切换工作区。
- 新设备是普通用户。管理员仍由桌面启动器、显式 bootstrap 或部署配置提供。单个普通设备不会因为重启服务而自动成为管理员。
- 自动登录不代表所有请求匿名访问。业务接口继续校验设备凭据和数据归属，各设备的数据仍然隔离。AI 提案仍需用户确认；DeepSeek 服务密钥与设备登录无关。

## 接口与实现

`POST /api/auth/device` 接收 `{ "deviceKey": "device_…" }`。后缀是 43 位 Base64URL 字符，完整凭据 50 字符，兼容现有 64 字符数据库字段，无需更改数据库结构。接口返回与 `/api/auth/verify` 相同的身份信息，不在响应、日志或页面显示凭据。

注册按凭据幂等；重复请求不会产生重复账号，不允许通过该接口注册任意旧 API Key，也不会改写已有账号的名称或权限。每个服务进程每分钟最多接受 60 个新设备，已有设备重连不消耗此额度。空库没有配置 bootstrap 时也能正常启动。

Windows 桌面端继续在加载应用前注入其 DPAPI 保护的已有本机凭据；浏览器自动登录先验证它，保持桌面数据兼容。当前用户界面变化由共享前端提供，已安装桌面包需要重新构建后才会包含这次修改。
